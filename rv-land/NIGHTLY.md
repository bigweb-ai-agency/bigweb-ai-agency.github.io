# Nightly research runbook

Current owner criteria (23 November 2026): this automation researches property, not RV vehicles for sale (those have a separate chat). Prioritize Minnetonka/MSP and Chicago ORD within about150km, with MN/IL/IN/WI/OH before the next nationwide low-count rotation. Manual regional budget is up toUSD20000; the nationalUSD3000–15000 collector remains separate. Keep real houses with and without garages, existing workshops and prepared outdoor areas as research leads even when RV dimensions/repair permission are unknown. Label building restoration, an occupied trailer lot and unknown surface readiness separately; do not require a confirmed full match just to retain a genuine listing. The owner does not plan to construct new buildings. Land-lease manufactured homes do not purchase the underlying land.

Read and rotate live rechecks of `data/midwest-shortlist-2026-11-23.json` and `data/airport-shortlist-2026-11-23.json` as well as national records. Preserve their stable IDs and histories; do not pass Midwest rows through the Pennsylvania/PIT adapter. `availability.js` keeps closed records out even in archive and requires a live active check within14days for current US results. Do not disable this gate to refill the map. Where exact coordinates are unknown, keep them null and retain a separately labelled approximate community/city locator; never invent parcel pins. Coordinate concurrent site work with fresh Git status/main and an isolated worktree; never stage another chat's RV-vehicle files.

1. Read README.md, current data/monitor.json and data/research-runs.json when present, Git status and fresh remote main. Use the last research entry's next_states to rotate coverage; it records deferred candidates and source-access failures. Work on a codex/ branch; preserve unrelated work.
2. Inspect the actual last workflow result. If it failed, identify the error. Do not silently label it operational. A blocked source preserves facts and history.
3. Expand public research beyond LandCentury using live/indexed pages or connected Chrome. Prioritize real garages/workshops with vehicle entry and states below ten photo candidates. Rotate states rather than repeatedly filling cheap desert subdivisions.
4. Record exact URL, full cash price, known fees, source status/date, state/county/parcel, coordinates and a genuine listing image URL. Quotes remain short. Do not import full descriptions or seller contact data. A search count is not proof of available suitable properties.
   An explicit starting bid is an auction even if a portal places it in cashPrice. Preserve the observed bid and price_basis in history, keep total_known null, and exclude it from fixed-cash candidates. A changed price basis is material even when the numeric amount stays the same. Never display an auction bid as a purchase total.
5. Keep storage, occupancy, personal repair and commercial use separate. A seller claim never becomes authority confirmation. For strong candidates inspect adopted county/city ordinances, zoning and restrictions. Meeting proposals are not adopted rules. No seller contacts, purchases or bookings.
6. Merge using merge_records. Preserve IDs, first_seen, histories, files and alternative URLs. Do not replay old indexed snapshots as fresh observations. Only definite evidence changes availability; a failed HTTP request does not.
7. Use cache_photos.preserve to retain actual image bytes under assets/listings/. Never delete previous files, use a generic image or synthesize a listing photo. A failed photo is a research gap, not a success.
8. Run make_analysis.py, focused unit tests, validate_data.py, JS syntax check if code changed, and proportionate Chrome UI checks. Compare pre/post IDs and photo availability.
9. Commit only allowed files, recheck remote main, merge without force, push and verify the public URL and Pages build. When app.js changes, update its version query in index.html and verify the changed behavior in connected Chrome; fresh JSON with cached old JavaScript is not a completed UI release. A failed publication is unfinished work.
   Before publishing listing changes, check for an active discovery run and let it finish, then fetch its result. Script pushes run tests and validation only; public discovery, data commits and the explicit Pages build request run on schedule or workflow_dispatch. GitHub Pages handles normal main pushes separately. If a collector publication fails on a Git merge conflict, inspect the failed step and start a new workflow_dispatch from current main; rerunning the stale checkout can repeat the conflict. Preserve source errors and distinguish collection success from publication success.
   If an existing source ID/URL changes parcel together with county/state, a large location move or a major area change, merge_records retains the old facts and freshness, records the conflicting observation and puts the old record on review hold. Do not treat a reused ID as a price change or as evidence the original property was sold. Correct mistaken imports transparently while retaining their history with an invalid_observation annotation and all image files.
10. Weekly: refresh flexible two-week return flights from VNO, UK and other EU hubs. Keep dates/party/baggage/source uncertainty. Positioning is a separate cost; never add unrelated minima to claim a same-date total.
11. Notify only for materially useful new candidates, changes, failure or necessary action. No routine unchanged-status messages.

The initial batch inspected all 50 states. Some have insufficient results in budget. Continue searching, but never invent records to hit a quota.
